# 从原始交互到可训练分布：面向具身智能的数据准备、数据引擎与自进化综述

**版本：v1.1｜检索截止：2026-08-02｜配套笔记库：211 项论文与技术报告**

> 本文讨论的“具身智能数据准备”不是狭义的数据清洗，而是将原始人类或机器人交互转化为目标具身策略可学习、可泛化、可安全部署的训练分布。它涵盖数据源设计、采集、接入检查、跨本体标准化、自动标注、切分与重标注、质量筛选、数据混合、增强与合成、物理验证、训练反馈以及在线失败回流。

## 摘要

具身基础模型的发展正在从“模型中心”转向“模型—数据—环境协同”。现实机器人数据昂贵、异构且长尾明显；人类视频虽然规模巨大，却缺少机器人动作与状态；仿真和生成数据具有可扩展性，却存在视觉、动力学和接触真实性差距；跨机构汇聚的数据又具有本体、控制频率、坐标系、传感器、语言粒度和任务定义不一致的问题。因而，训练数据量并不是一个充分统计量。决定最终闭环性能的，是原始数据经过何种变换成为怎样的训练分布，以及这种分布是否与目标策略、训练阶段、目标本体和部署环境匹配。

本文基于 211 项论文、技术报告与数据系统工作，系统梳理面向具身智能的数据准备。与按“机器人数据、人类视频、仿真数据、生成数据”等来源划分的综述不同，本文采用**操作中心和闭环中心**的视角：数据经历了什么处理，处理依据什么质量信号，价值如何通过训练和真实执行被验证。我们提出一个八阶段 taxonomy：数据源与采集设计、接入与技术质量控制、标准化与跨本体对齐、语义丰富化、筛选与配比、增强与合成、多层验证、训练及部署反馈。基于文献证据，本文得到六个主要判断。第一，数据质量是相对于学习器和部署分布定义的条件量，而不是数据自身的固定属性。第二，具身数据准备的关键粒度正在从“数据集/轨迹”下沉到“子任务/片段/状态转移”。第三，跨本体规模化的前提是表示、运动和行为对齐，而不只是张量维度一致。第四，同一来源在预训练、后训练、恢复、安全和验证中的角色不同，训练角色往往比“真实/仿真/生成”标签更能解释价值。第五，合成与自训练把瓶颈转移到独立、分层且经过真机校准的验证。第六，失败数据只有经过类型化标注和目标路由才有价值；未来系统将沿“静态准备—学习器相关选择—失败驱动后训练—多轮数据引擎—自主数据准备代理”演进。

最后，本文提出 **EvoDataPrep** 研究框架：用可组合的数据算子、策略相关的数据价值估计、分层验证器和主动采集器，自动搜索针对特定 VLA、任务和本体的数据准备流水线。该方向可形成独立于具体 VLA 架构的研究问题、基准和系统。

## 1. 为什么具身智能需要独立的数据准备研究

### 1.1 数据规模增长没有消除数据瓶颈

Open X-Embodiment、DROID、BridgeData、RoboNet、AgileX、GR00T、Qwen-RobotManip、Xiaomi-Robotics-1 和 LingBot-VLA 2.0 等工作不断扩大数据规模，但这些数据不是同分布样本的简单叠加。它们来自不同机器人、不同采集界面、不同控制频率、不同相机配置、不同动作空间和不同任务规范。一个能够读取百万级轨迹的训练程序，并不自动拥有一个一致的训练分布。[论文笔记 P001–P025, P157–P186]

近期工作进一步说明，更多数据有时会降低性能。数据可能包含失败、停滞、误操作、控制抖动、错误语言、重复状态、长时间空动作、相机与状态不同步、动作饱和、异常关节、不可达目标和分布冲突。即使一条演示在视觉上“干净”，它也可能因为动作表示不兼容、任务覆盖冗余或与当前策略已经掌握的区域重合而价值很低。[P046–P074]

### 1.2 具身数据比文本和图像数据更难准备

文本或图像样本通常可以独立判断语言质量、重复度、毒性或图文一致性。具身样本具有更强的时序、因果和物理约束：某一时刻的图像必须与状态和动作同步；动作必须在指定坐标系和时间尺度下有意义；轨迹价值依赖前后状态转移；接触、抓取和恢复行为不能只从单帧外观判断；同一轨迹对不同本体和不同策略可能产生不同作用。

因此，具身数据准备至少同时面对八类质量：

| 质量维度 | 典型问题 | 代表性处理 |
|---|---|---|
| 技术质量 | 丢帧、时间戳漂移、损坏文件、传感器不同步 | 完整性检查、重采样、对齐、异常检测 |
| 控制质量 | 抖动、饱和、不可达、过长 idle、频率不一致 | 平滑、裁剪、频率对齐、可达性检查 |
| 行为质量 | 失败、绕路、重复尝试、恢复、次优但可用 | 分段评分、失败/恢复标注、局部降权 |
| 语义质量 | 指令错误、粒度不一致、动作和语言错配 | VLM 重标注、状态转移描述、子任务切分 |
| 物理质量 | 穿透、悬浮、接触错误、动力学不可信 | 几何/运动学/动力学/接触验证 |
| 覆盖质量 | 场景、物体、技能和失败模式不足或重复 | 去重、聚类、覆盖优化、主动采集 |
| 对齐质量 | 本体、动作空间、相机、任务定义不一致 | 规范动作空间、mask、坐标变换、行为上下文 |
| 策略价值 | 样本是否真正改善目标策略 | 影响估计、验证集损失、rollout、闭环成功率 |

### 1.3 数据准备应成为独立研究对象

现有论文常把数据准备隐藏在附录或 technical report 中，把清洗、重标注和混合比例视为工程细节。然而 Qwen-RobotManip、Xiaomi-Robotics-1、LingBot-VLA 2.0、π0.5、ABot-M0 等系统显示，模型能力与数据配方难以分离：统一动作表示、筛选规则、语义标注、源数据角色和后训练混合比例，往往直接决定跨任务和跨本体泛化。[P162, P168, P172, P176, P184]

这使得“面向具身智能的数据准备”具备成为独立方向的三个条件：它有独立的输入输出和优化目标；它包含尚未解决的算法问题，而非单纯人工规则；它可以通过统一基准与下游闭环性能进行评价。

## 2. 调研范围与阅读方法

### 2.1 收录范围

配套论文笔记库收录 211 项工作，其中 68 项为数据或方法章节深读，109 项为方法级阅读，34 项为摘要级扩展索引。文献覆盖八类来源：

1. 机器人数据集、采集系统与跨机构汇聚；
2. 人类视频、第一视角视频和跨域迁移；
3. 数据质量评估、筛选、去重、混合和课程学习；
4. 自动标注、动作分段、语言重标注和失败建模；
5. 仿真、重放、轨迹变换、视频/世界模型生成与数据增强；
6. 在线后训练、主动采集、失败回收和策略自进化；
7. VLA、机器人基础模型和企业 technical report 中的数据配方；
8. LLM 与多模态基础模型的数据准备方法，作为机制迁移的灵感来源。

本文不试图声称穷尽所有机器人学习论文。纳入标准是：工作对“原始数据如何变成训练数据”提供了可辨认的方法、系统或实证，而不是仅仅使用某个现成数据集。

### 2.2 操作中心的阅读模板

每篇论文统一回答四个问题：

- **处理对象是什么：** 数据源、整条轨迹、子任务片段、状态转移、帧、标签还是数据混合比例？
- **执行了什么操作：** 采集、过滤、切分、对齐、重标注、增强、合成、重加权、路由还是回流？
- **依据什么信号：** 人工规则、统计量、表示相似度、互信息、VLM、奖励、验证损失、影响函数、仿真回报还是真机成功率？
- **如何验证价值：** 内在质量指标、离线预测、固定训练预算下的策略性能、闭环 rollout、跨环境泛化还是安全指标？

这种模板避免把“规模大”“自动化”或“检测准确率高”直接等同于训练价值。

## 3. 统一问题定义

### 3.1 输入、流水线与输出

一条原始交互记录可以抽象为：

```text
e = (metadata, observations[1:T], states[1:T], actions[1:T],
     language, task_context, outcome, provenance)
```

数据准备流水线由一组可组合算子构成：

```text
P = Acquire → Validate → Align → Segment → Label → Score
    → Filter/Weight/Route → Augment/Synthesize → Verify → Package
```

流水线输出不应只是一组被保留的轨迹，而应是带有训练角色和谱系信息的样本：

```text
D_train = {(x_j, target_j, weight_j, role_j, provenance_j, version_j)}
```

其中 `role` 可以区分通用预训练、目标本体对齐、任务后训练、恢复训练、负例或安全边界数据。`provenance` 记录原始来源和所有变换，`version` 支持数据—模型联合回溯。

### 3.2 优化目标

数据准备的目标不是最大化静态“质量分数”，而是在数据、训练和真实执行预算下最大化目标部署效用：

```text
maximize  ExpectedDeploymentReturn(policy trained on P(D_raw))
          - λ · DataPreparationCost
          - μ · TrainingCost
          - ν · SafetyAndDistributionRisk
```

这一定义有三个含义。首先，质量与目标策略、任务、本体和训练阶段有关。其次，筛选、加权、合成与采集应统一优化，而不是相互独立。第三，最终评价必须包含下游训练与闭环执行，而不能只看过滤器自身准确率。

### 3.3 数据价值的条件性

可将样本价值写成一个条件函数：

```text
Value(e | model, embodiment, task distribution, training stage, budget)
```

同一段轨迹可能对通用预训练有价值，对精细操作后训练却过于粗糙；对六自由度机械臂可直接使用，对灵巧手只提供视觉先验；对初始策略是关键探索，对成熟策略则是冗余数据。ATHENA、Re-Mix、SIEVE、互信息筛选和 demonstration curation 研究共同说明，数据价值不能脱离学习器和数据组合来判断。[P049–P061, P066]

## 4. 一个端到端 taxonomy：从数据源到闭环控制器

本文把具身数据准备划分为八个连续但可迭代的阶段。

| 阶段 | 核心问题 | 主要输出 | 代表性工作 |
|---|---|---|---|
| 1. 数据源与采集设计 | 采什么、由谁采、如何覆盖长尾 | 原始人类/机器人/仿真交互 | DROID、UMI、AXIS、AutoRT、AgileX [P002, P007, P014, P135] |
| 2. 接入与技术质量控制 | 数据是否完整、同步、可解析 | 通过 schema 与技术检查的数据 | LingBot-VLA 2.0、Green-VLA、DEED [P154, P176] |
| 3. 标准化与跨本体对齐 | 不同本体和控制接口如何共训 | 统一观测、动作、时间和 mask | RT-X、π0.5、Qwen、Xiaomi、UniACT [P001, P011, P162, P168, P172] |
| 4. 语义丰富化 | 原始流如何变成指令与子任务 | 语言、阶段、对象、行为和结果标签 | NILS、SPARC、Qwen、Xiaomi、Gemini ER [P076, P080, P092, P094] |
| 5. 筛选、加权与混合 | 哪些数据以多大权重进入何阶段 | 子集、权重、课程和数据角色 | Re-Mix、CUPID、DataMIL、ATHENA、SIEVE [P049, P052–P055, P066] |
| 6. 增强与合成 | 如何低成本扩展覆盖 | 变换轨迹、仿真或生成样本 | MimicGen、RoVi-Aug、RoboEngine、Genie Sim [P095–P133] |
| 7. 分层验证 | 合成/重标注数据是否可信 | 通过语义到闭环门控的数据 | AXIS、RoboEngine、Xiaomi-U0、world-model verifier [P007, P126] |
| 8. 训练与部署反馈 | 哪些失败应回流，下一批采什么 | 新数据请求和更新后的流水线 | RoboCat、AutoRT、RECAP、ROVE、Seed2Scale、LWD [P134–P154] |

该 taxonomy 的关键不是线性流程，而是反馈边。训练中的高损失样本、仿真 rollout 的失败类型、真实部署的恢复行为和安全事件，应反向更新筛选器、采集任务、合成条件和数据混合比例。

## 5. 数据源设计与采集：数据准备始于“采什么”

### 5.1 真机遥操作与分布式采集

DROID、BridgeData、RoboNet、AgileX 和 Open X-Embodiment 奠定了大规模真机数据的基础。它们的贡献不仅是轨迹数量，还包括采集协议、硬件校准、元数据、场景多样性和统一发布格式。[P001–P006, P019–P025]

从数据准备角度看，采集阶段包含四类设计决策：

- **任务分布设计：** 是围绕预定义技能收集高成功率数据，还是让操作者在开放环境中覆盖对象、场景和失败？
- **控制接口设计：** 示教器、VR、双臂遥操作、手持夹具或第一视角设备决定动作精度、操作者负担和可迁移性。
- **记录 schema：** 相机、深度、状态、力觉、触觉、动作、语言、时间戳、机器人标定和环境元数据是否同时保存。
- **在线质量反馈：** 采集者是否实时看到成功检查、覆盖缺口、异常轨迹和重复任务提示。

AXIS 代表“数据采集即数据流水线”的路线。它把浏览器遥操作、任务生成与验证、成功判断、质量过滤、轨迹平滑和视觉/物理增强集成在同一系统中，使数据问题尽量在进入训练前暴露。[P007] 相比之下，传统做法常在采集结束后才发现视角遮挡、任务重复、动作抖动或标定错误，导致整批数据报废。

### 5.2 UMI 与人类示范：扩大数据源，但引入域差距

UMI、DexUMI、TacUMI、ActiveUMI 和 RealDexUMI 通过便携式示教设备收集人类操作，降低对目标机器人在线占用的依赖。[P014–P018] 这类数据具有高场景多样性和低采集成本，但需要额外解决：

1. 人手、示教器与机器人末端执行器的几何差异；
2. 人类运动速度、自由度和接触方式与机器人不同；
3. 第一视角或手持相机的视觉分布与机器人相机不同；
4. 人类行为通常没有规范语言和成功标签；
5. 轨迹可能超出目标机器人工作空间或碰撞约束。

因此，UMI 类数据通常需要标定、末端轨迹恢复、机器人可达性检查、手部去除或视觉域适配、动作重定向以及机器人数据后训练。Xiaomi-Robotics-1 的配方尤其清晰：先用大规模 UMI 建立通用视觉—动作先验，再用目标机器人数据对齐动作执行和部署分布。[P172]

### 5.3 自主探索与车队数据：采集由策略驱动

AutoRT、RoboCat、LWD、ROVE、Seed2Scale 和 SOP 把采集从固定任务清单转为策略驱动过程。[P134–P150] 系统在真实环境中生成或选择任务、执行当前策略、记录成功与失败，再决定哪些数据进入下一轮训练。此时采集本身成为主动学习问题：

```text
下一条数据的价值 = 预期性能增益 / 采集成本
```

有效的主动采集不能只挑选高不确定性状态，因为高不确定性可能来自传感器噪声、不可达任务或安全边界。更合理的标准应同时考虑模型不确定性、任务重要性、可执行性、覆盖增益、风险和数据可复用性。

### 5.4 数据源应按“角色”而非“优劣”组织

文献表明，不同来源的优势互补：人类视频提供广泛语义和物体交互先验，UMI 提供接近操作的连续运动，仿真提供精确状态和长尾可控性，真机遥操作提供动作与物理对齐，在线 rollout 提供当前策略真正遇到的失败。因而，合理的数据系统不应把来源简单排序，而应为其分配角色：

| 数据角色 | 更适合的数据源 | 主要监督 |
|---|---|---|
| 通用视觉—语义预训练 | 网络视频、第一视角视频、图文数据 | 对象、场景、意图、过程 |
| 运动与操作先验 | UMI、人类动作、重定向轨迹 | 末端运动、阶段结构 |
| 跨本体预训练 | 多机器人汇聚数据 | 共享视觉—动作结构 |
| 目标本体对齐 | 真机遥操作、目标机器人自主数据 | 精确控制、接触与动力学 |
| 任务后训练 | 高质量成功示范、纠正数据 | 目标技能和任务组合 |
| 恢复与安全训练 | 失败、retry、人工接管、边界事件 | 恢复、停止、风险规避 |

这一“角色路由”比单一质量分数更符合 π0.5、Xiaomi-Robotics-1、Qwen-RobotManip 等分阶段训练配方。[P162, P168, P172]

## 6. 接入、标准化与跨本体对齐

### 6.1 技术接入检查：最基础但最常被忽略

在模型训练前，数据需要通过 schema、文件、时间和传感器层面的检查。常见算子包括：

- 文件可读性、字段完整性和版本兼容检查；
- 时间戳单调性、图像—状态—动作同步检查；
- 相机内外参、机器人 URDF 和关节限制校验；
- 缺帧插值、统一采样频率和动作延迟估计；
- 异常关节、速度、加速度、jerk、动作饱和与静止比例检测；
- 图像模糊、过曝、遮挡、镜头污染和相机移动异常检测；
- 任务元数据、成功标签和语言字段一致性检查。

LingBot-VLA 2.0 报告了较完整的多级筛选：机器人数据从约 9 万小时原始池经过 jerk、Z-score、静止段、URDF/视频—状态一致性和人工视觉检查后保留约 5 万小时；第一视角数据还需要 VLM、SLAM、手部可见性、覆盖度和生理可执行性检查。[P176] Green-VLA、DEED 等工作也显示，控制频率与视觉时间对齐本身可显著影响训练稳定性。[P149, P154]

### 6.2 动作表示统一不是简单 padding

Open X-Embodiment 通过共同格式实现跨数据集训练，但后续工作逐渐发现，张量形状一致只是第一步。[P001] 跨本体动作标准化至少有四层：

1. **坐标层：** 关节空间、基座坐标、世界坐标、相机坐标或末端执行器坐标；
2. **控制量层：** 绝对位姿、增量位姿、速度、力/力矩、离散动作或动作 chunk；
3. **时间层：** 控制频率、动作延迟、chunk 长度、插值和积分方式；
4. **语义层：** 同一维度对不同机器人是否代表相同自由度，夹爪开合与灵巧手关节如何对应。

近期 VLA 常使用固定长度的规范动作向量加 embodiment mask。Qwen-RobotManip 使用高维规范向量和缺失维度 mask，并强调相机坐标中的末端增量与相机—本体位置编码；Xiaomi-Robotics-1 使用统一末端坐标和固定向量；LingBot-VLA 2.0 使用规范动作空间并显式处理不同本体自由度。[P168, P172, P176]

然而 mask 只告诉模型“哪些维度存在”，并不保证动作语义一致。更进一步的研究需要学习本体条件动作表示，显式编码运动链、末端类型、控制器和动力学，而不是仅依赖手工槽位。

### 6.3 时间对齐决定动作监督是否成立

机器人日志中的图像时间、状态采样、控制命令发出时间和实际执行时间往往不同。错误对齐会使模型学到“看到结果后才输出原因动作”的伪相关。可采用的处理包括：

- 根据硬件时间戳重新同步；
- 用光流、末端运动或状态变化估计视觉—动作延迟；
- 对不同频率进行抗混叠重采样；
- 对动作 chunk 重新定义起止时刻；
- 对长延迟系统保留命令与执行状态双时间线。

Green-VLA 使用光流辅助时间对齐；DEED 强调控制频率对齐；这类细节应被纳入统一数据标准，而不是留给每个训练代码库独立处理。[P149, P154]

### 6.4 跨域转换必须共同变换视觉、动作和语言

镜像、时间反转、视角变化、场景重建或人类到机器人迁移，会同时改变图像、动作和语言语义。只变图像不变动作会制造错误监督。例如左右镜像应改变水平运动方向和“左/右”语言；时间反转只对具有可逆动力学和可逆任务语义的片段成立；相机位姿改变后，基于相机坐标的动作也必须转换。

这一原则可概括为：

```text
有效增强 = 对 observation、action、state、language、task semantics 的一致共变换
```

它是视觉增强与机器人数据增强最本质的差异。

## 7. 自动标注、切分与重标注

### 7.1 为什么轨迹需要重新语义化

原始机器人日志通常只有粗粒度任务名，甚至完全没有语言。直接用整条长轨迹配一个指令会产生三个问题：同一指令对应大量无关前后文；中间失败和恢复被错误视为成功动作；模型难以学习可复用的子技能。因而，自动语义化通常包含：

```text
对象与状态识别 → 事件检测 → 子任务边界 → 动作/阶段标签
→ 状态转移描述 → 指令重写 → 成功/失败/恢复标签
```

### 7.2 从视频变化推断语言：NILS 路线

NILS 使用对象检测、分割和状态变化，在没有人工逐帧标注的长视频中自动产生子任务与语言标签。[P076] 其重要意义是把标注依据从“视频整体语义”下沉到“可观察状态变化”。对具身数据而言，描述“把杯子放到桌上”比描述“一个人在整理厨房”更接近动作监督。

但纯视觉变化也存在歧义：遮挡可能被误判为物体消失；接触并不等于抓取成功；视觉相似状态可能具有不同约束。未来标注器应融合机器人状态、力觉、深度、对象轨迹和任务图。

### 7.3 结构化动作切分：SPARC、Qwen 与 LingBot

SPARC 把长轨迹拆成与对象、末端轨迹和夹爪阶段相关的子任务，并为片段计算可靠性。[P080] Qwen-RobotManip 使用结构化行为上下文，把目标、对象、动作阶段和执行状态编码到训练提示中；LingBot-VLA 2.0 使用 VLM 自动切分并归纳行为类别，同时移除 idle 片段。[P092, P093]

这些工作共同显示，**子任务片段是比整条 episode 更有用的数据准备单位**。片段级处理可以：

- 保留成功轨迹中的高质量部分；
- 丢弃或降权局部错误，而不是删除整个 episode；
- 组合不同轨迹中的可复用技能；
- 对失败、retry 和恢复进行独立建模；
- 更精确地平衡技能和对象覆盖。

### 7.4 VLM 标注需要自己的质量控制

VLM 可自动生成指令、状态描述、对象标签和动作分段，但不能把模型输出直接视为真值。建议采用以下验证链：

1. 使用视觉证据检查对象和状态是否存在；
2. 使用动作/机器人状态检查描述是否与运动一致；
3. 对关键标签使用多模型或多提示一致性；
4. 通过任务前后状态变化验证动作结果；
5. 将低置信度或冲突样本路由给人工复核；
6. 追踪标注模型、提示和版本，避免标签漂移无法定位。

Xiaomi-Robotics-1 用 VLM 生成固定时长的状态转移描述，是将视频/UMI 数据转为语言条件训练数据的典型做法。[P172] 其启发是：对连续操作，状态转移语言通常比开放式视频 caption 更稳定、更贴近控制。

### 7.5 失败和恢复不应被统一当作脏数据

传统 imitation learning 常只保留成功演示。但 ReTVL、retry 学习、RECAP、ROVE、SOP 等工作表明，失败附近包含策略最需要的信息。[P060, P136–P150] 关键在于区分：

- **无信息噪声：** 传感器损坏、随机抖动、错误标定；
- **局部操作错误：** 可降权错误动作，但保留之前的有效路径；
- **有价值 retry：** 明确展示错误检测与第二次尝试；
- **恢复轨迹：** 从分布外状态返回可控区域；
- **安全边界事件：** 应学习停止、撤回或请求人工，而非模仿危险动作。

ReTVL 的思路是利用 retry 事件提供稀疏监督，对局部错误降权，同时保留后续恢复。这比以 episode 成功标签删除整条轨迹更细致。[P060]

## 8. 数据质量评估、筛选、加权与估值

### 8.1 第一代：规则和统计量

最常见方法根据成功标签、轨迹长度、平滑度、速度/加速度/jerk、idle 比例、动作范围、图像清晰度、状态变化和人工规则筛选。这类方法便宜、可解释，适合发现技术错误和明显异常，也是工业流水线不可缺少的第一道门。

局限是规则只能表达已知缺陷，而且容易把策略风格误判为质量。例如，较长轨迹可能是低效，也可能包含必要探索或困难场景；大 jerk 可能是噪声，也可能来自快速接触；失败 episode 中可能包含高质量恢复片段。

### 8.2 第二代：表示、信息量与学习难度

互信息筛选、表示聚类、覆盖度、重复度、状态变化、进度模型和可学习性估计，试图发现规则之外的结构。[P050, P062] 其核心问题从“是否有缺陷”转为“是否提供新的、可学习的信息”。

可用信号包括：

- 样本与已有数据在视觉、语言、动作或状态空间中的新颖度；
- 轨迹内部 observation—action 或前后状态的互信息；
- 对象、场景、技能、接触模式和失败类型的覆盖；
- 学习曲线或小模型对样本的可学习性；
- 片段是否连接了可复用的技能状态。

Data Assessment for Embodied Intelligence 尝试用多模态多样性与可学习性进行训练前评估。[P062] 这类方法适合大规模数据池的低成本预筛，但仍是策略无关代理指标。

### 8.3 第三代：策略相关的数据选择

Re-Mix、CUPID、DataMIL、ATHENA、SIEVE 等方法把数据价值与目标训练任务联系起来。[P049, P052–P055, P066]

- **Re-Mix** 学习不同来源的混合权重，使训练分布更接近目标任务，而不是按原始数据规模采样。
- **CUPID/DataMIL** 尝试在片段或轨迹层估计数据对子任务和策略学习的贡献。
- **ATHENA** 将影响函数扩展到超大规模多任务 VLA，用近似方法估计训练样本对验证目标的影响。
- **SIEVE** 识别可复用 primitive 和关键 transition，以较少数据和训练步数保留或提升性能。

这一代方法的重要转变是：一个样本是否“高质量”，由它对目标验证分布的边际贡献决定。相应地，输出也不一定是二值保留/删除，而可以是权重、课程顺序、训练阶段、任务路由或只用于某个技能头。

### 8.4 过滤器检测准确率不等于策略性能

《What Demonstration Curation Metrics Do to Your Policy》给出一个关键警告：更善于检测人工缺陷的指标，未必产生更好的下游策略；某些指标会受 episode 长度等混杂因素影响。[P061] 这意味着筛选研究必须报告两类结果：

1. 过滤器是否识别已知损坏或人工质量标签；
2. 固定训练预算后，筛选数据是否真正改善闭环成功率和泛化。

只报告 AUROC、相关系数或人工偏好，不能证明数据准备有效。

### 8.5 第四代：闭环数据价值与在线路由

最直接的数据价值信号来自实际训练和执行：验证集损失变化、仿真成功率、真机成功率、人工接管率、恢复率、安全事件和新技能获得。RECAP、ROVE、Seed2Scale、LWD 和 SOP 通过在线经验把筛选与采集连接起来。[P136–P150]

未来可将数据评分建模为多目标向量，而不是单一分数：

```text
score(e) = [technical_validity,
            semantic_consistency,
            novelty,
            learnability,
            target_alignment,
            recovery_value,
            safety_risk,
            estimated_policy_gain,
            processing_cost]
```

流水线根据训练阶段和预算选择不同组合。例如，预训练重视覆盖和可学习性，目标任务后训练重视策略增益和精确动作，安全阶段重视风险边界与恢复价值。

## 9. 数据混合、采样、课程与角色路由

### 9.1 为什么固定比例不可靠

多源 VLA 训练常同时使用图文、视频、跨本体机器人、目标本体、仿真和合成数据。直接按数据量采样会让最大来源支配训练；均匀采样又可能过度放大狭小或低质量来源。更复杂的是，不同来源之间可能正迁移、冗余或冲突。

因此，数据混合需要回答三个问题：

- 每个来源在不同训练阶段占多少比例？
- 某类样本应该训练哪些输出或参数，而不是所有目标？
- 配比是否应随模型能力和验证表现动态变化？

### 9.2 学习混合比例

Re-Mix 与 LLM 领域的 DoReMi 都表明，可以用小规模代理训练或验证目标学习数据域权重，而非手工设定。[P049, P191] 对具身数据，这一思想可以扩展为多层权重：来源权重、任务权重、本体权重、技能权重、片段权重和时间步权重。

但代理模型与目标 VLA 的排序可能不一致。可靠方案应周期性用目标模型校准代理，并报告混合策略对训练规模变化的稳健性。

### 9.3 分阶段配方比单一数据池更常见

π0.5 将 web、跨本体、目标机器人和高质量后训练数据分配到不同阶段；Xiaomi-Robotics-1 先用大规模 UMI 和视觉语言数据建立先验，再以机器人数据对齐；Qwen-RobotManip 把多平台数据转为规范动作表示并加入行为上下文；LingBot-VLA 2.0 对机器人数据与第一视角数据采用不同筛选和语义化流程。[P162, P168, P172, P176]

这些配方支持一个统一观点：

> 数据的用途应由“来源 × 质量 × 语义粒度 × 本体匹配 × 训练阶段”共同决定。

### 9.4 课程学习与难例调度

课程不应简单从短轨迹到长轨迹，而应考虑：感知难度、动作精度、接触复杂度、任务组合长度、分布外程度、恢复需求和当前策略能力。理想的数据调度器持续维护技能图和能力估计，优先训练“略高于当前能力且可学习”的片段，同时保留一定比例的基础数据防止遗忘。

### 9.5 多样性存在收益递减甚至反转

数据多样性通常有利于泛化，但不受约束的异构数据会引入冲突监督。跨本体数据可能在视觉表征上有益，却在动作头上造成负迁移；人类视频适合语义预训练，却不应被当作精确机器人动作标签。因而，增加多样性时应同时增加条件信息、mask、路由或模块化参数，使模型知道“这条数据来自何种本体、控制器和监督角色”。

## 10. 数据增强与合成：扩展覆盖，而不是复制外观

### 10.1 增强方法的五个层次

具身数据增强可以按改变的对象分为五层：

| 层次 | 典型方法 | 可扩展内容 | 主要风险 |
|---|---|---|---|
| 视觉层 | 颜色、光照、背景、纹理、遮挡、相机噪声 | 外观鲁棒性 | 图像与状态/动作不一致 |
| 几何层 | 视角变化、场景重建、物体位姿变化 | 空间覆盖 | 相机坐标动作未同步变换 |
| 轨迹层 | 镜像、平移、重定向、轨迹拼接、时间处理 | 运动和初始状态覆盖 | 不可达、碰撞、动力学错误 |
| 任务层 | 对象替换、目标条件变化、子任务组合 | 任务长尾 | 语言和成功条件错误 |
| 生成层 | 视频模型、世界模型、仿真生成、agentic scene generation | 大规模新场景和新轨迹 | 物理幻觉与反馈偏差 |

单纯视觉增强主要改善感知鲁棒性；要真正扩展控制分布，必须改变状态—动作—任务联合分布，并保持物理与语义一致。

### 10.2 从少量示范生成大量轨迹：MimicGen 谱系

MimicGen 从少量人工示范中识别对象相对的子任务轨迹，通过改变对象布局并重新执行，生成大规模机器人示范。[P103] 其后续 DexMimicGen、SoftMimicGen 和 DynaMimicGen 扩展到灵巧操作、柔性物体和动态条件。[P104–P106]

这条路线的核心不是“复制轨迹”，而是利用任务结构对轨迹进行可执行变换：

```text
种子示范 → 子任务分解 → 对象/坐标变换 → 轨迹重构
→ 控制器执行 → 成功检查 → 保留或修复
```

其优势是动作和物理结果来自仿真或机器人执行，通常比纯视频生成更可信；局限是依赖可获得的对象位姿、任务分解和适当控制器，且生成分布受种子示范结构限制。

### 10.3 视觉与场景增强必须保留动作条件

RoboEngine、RoVi-Aug、GenAug、ROSIE 等工作改变背景、物体、相机或场景外观，以提高视觉泛化。[P095–P102, P107–P118] 对这类方法，最低验证要求是确保增强后：

- 被操作对象和目标位置仍可见且语义正确；
- 遮挡没有删除完成任务所需的信息；
- 相机变化与相机坐标动作同步更新；
- 物体几何和尺度与抓取动作相容；
- 语言中的对象、位置、颜色和方向被同步修改；
- 增强没有泄露训练标签或制造不可能状态。

视觉 realism 不是充分条件。一个高度逼真的场景，如果夹爪与目标存在毫米级错位，也可能形成有害动作监督。

### 10.4 人类视频到机器人数据的转换

人类视频规模远大于机器人数据，因此多项工作尝试恢复手部/对象轨迹、估计深度和相机运动，再将其转为机器人动作或中间表示。[P026–P045] 常见流程包括：

```text
人类视频 → 手/对象/相机跟踪 → 3D 恢复 → 行为分段
→ 末端轨迹或 affordance → 本体重定向 → 仿真/运动学检查
→ 机器人视觉域转换 → 目标机器人微调
```

主要困难不是视觉重建本身，而是“人能做”不等于“机器人能做”。需要处理手指自由度、接触面、工具使用、速度、双手协调、工作空间、碰撞和末端类型差异。因而，更稳妥的用途是提取语义、对象关系、阶段结构和粗粒度末端运动，再由机器人数据完成精确控制对齐。

### 10.5 视频模型和世界模型作为数据生成器

近期工作开始用视频生成或世界模型产生候选未来、反事实场景和合成轨迹。[P119–P133, P151] 这类方法具有两种用途：

1. **表示与规划监督：** 生成可能的视觉未来、状态变化或任务过程，不必直接当作动作标签；
2. **合成示范：** 将生成视频进一步逆动力学或动作解码，转成可训练的 observation—action 数据。

第二种用途风险更高，因为视频的视觉连贯性不保证动作可执行、接触力合理或因果方向正确。世界模型还可能强化当前策略和训练数据的偏差，形成“模型相信的世界—策略产生的数据—再训练模型”的自证循环。

### 10.6 合成数据的分层验证栈

合成数据的研究重点应从“生成质量”转为“验证后有效产出率”。一个可推广的验证栈如下：

| 验证层 | 要回答的问题 | 可能的验证器 |
|---|---|---|
| 语义层 | 指令、对象、目标和结果是否一致 | VLM、状态变化规则、任务图 |
| 几何层 | 物体、手、机器人和相机关系是否合理 | 深度、重建、碰撞和可见性检查 |
| 运动学层 | 轨迹是否在关节、速度和工作空间内可达 | IK、URDF、关节限制、轨迹优化 |
| 动力学/接触层 | 力、接触、摩擦和稳定性是否可信 | 物理仿真、接触估计、力觉模型 |
| 策略层 | 当前策略能否从候选数据中获益 | proxy 训练、影响估计、离线评估 |
| 闭环层 | 执行是否成功且安全 | 仿真 rollout、真机小样本验证 |

理想指标不是生成了多少小时，而是：

```text
有效数据收益率 = 通过全部验证且带来策略增益的数据量 / 生成与验证总成本
```

### 10.7 生成与验证应是对抗关系

生成器负责扩大覆盖，验证器负责拒绝不可靠扩展。若两者由同一模型、同一提示或同一训练数据驱动，错误可能高度相关。更可靠的系统应使用异构证据：视觉模型检查语义，几何模块检查空间，物理引擎检查接触，目标策略或独立 evaluator 检查学习价值，少量真机验证校准整个链条。

## 11. 从离线流水线到数据自进化

### 11.1 数据自进化的定义

本文把“数据自进化”定义为：系统根据模型训练和部署反馈，自动改变下一轮数据的采集、筛选、标注、合成、混合或训练角色，并形成多轮改进闭环。它不同于一次性数据增强，也不同于只更新模型参数。

一个完整闭环包含：

```text
训练当前策略 → 评估/部署 → 定位能力缺口与失败模式
→ 选择数据操作（找、采、改、生成、重标注、重加权）
→ 多层验证 → 增量训练 → 回归与安全检查 → 新一轮
```

### 11.2 早期自改进系统：RoboCat 与 AutoRT

RoboCat 展示了多轮自生成数据和再训练：模型学习新任务后收集额外经验，再把经验加入训练池。[P134] AutoRT 将视觉语言模型、语言模型和机器人策略组合起来，在开放真实环境中提出可行任务并自主采集数据。[P135]

这类系统证明自主扩展数据可行，但也暴露三个问题：自主任务是否真正覆盖能力缺口；成功检查是否可靠；新数据是否会造成分布偏移或遗忘。

### 11.3 失败驱动的后训练

RECAP、ROVE、Seed2Scale、DeMaVLA 和 SOP 将当前策略的失败、人工纠正或高价值在线经验转为后训练数据。[P136–P150] 与离线成功示范相比，这些数据具有更强的策略相关性，因为它们正好位于当前决策边界附近。

常见机制包括：

- 收集当前策略失败，并由人工完成或纠正；
- 在失败点附近生成恢复或替代动作；
- 对成功、失败和纠正片段采用不同损失或权重；
- 用不确定性、失败聚类或覆盖缺口选择下一批任务；
- 使用安全 gate 或人工接管限制在线探索风险。

DeMaVLA 采用大规模双臂数据预训练，并在后训练中引入失败驱动和人工 gate 的 DAgger 类数据；SOP 强调通过分布式在线收集和纠正实现可扩展后训练。[P148, P150]

这些系统不能统一写成“收集失败后继续训练”。RECAP 把成功/失败终止标签、到达结果的时间、自动 rollout 与人工纠正转为价值和优势条件；报告中的多轮更新每次从共同预训练 checkpoint 重新微调，而不是从上一轮继续累积，以抑制漂移。[P136] SOP 是 actor–learner 数据系统：多个机器人异步上传完整 episode，任务间均匀采样，任务内依据近期 online/offline loss 动态调整配比，并把 online 比例截断在 0.2–0.8；新 checkpoint 只在 episode 边界替换。[P150] LWD 则用分布式价值学习吸收成功、失败、retry、部分进展与干预，在在线阶段冻结 VLM backbone、只更新 action expert 以降低不稳定性。[P149]

因此，失败驱动演化的核心变量至少有五个：失败的语义类型、数据单元粒度、奖励/纠正信号、online/offline replay 配比和允许更新的参数模块。只报告“新增多少小时失败数据”无法解释收益。

### 11.4 分布式车队学习与真实世界反馈

LWD 代表从分布式机器人车队收集经验并回流训练的路线。[P149] 车队数据具有真实部署分布和长尾失败，但同时带来设备版本、传感器、环境、操作者、网络和隐私差异。数据准备必须支持：

- 设备与软件版本元数据；
- 自动匿名化和敏感场景处理；
- 失败优先上传和带宽预算；
- 跨设备校准和异常检测；
- 灰度模型与数据版本对应；
- 回归任务保留与灾难性遗忘监测。

SOP 在 10 台机器人、三类真实任务上验证小时级在线后训练，LWD 在 16 台双臂机器人、八类任务上验证 offline-to-online RL。[P149–P150] 这些是各自设置内的数据系统证据，不是二者算法优劣的直接排名。Robot-Powered Data Flywheels 进一步说明，闭环更新对象不必是动作策略：真实部署产生的任务相关观测和环境标签也可反向改进上游视觉基础模型。[P211]

### 11.5 世界模型与策略共进化

World-VLA-Loop 等工作让世界模型生成或评估策略经验，同时用新 rollout 更新世界模型。[P151] 这一闭环可能提高数据效率，但容易出现共同偏差：世界模型忽略某类失败，策略便不会从中学习；策略避开世界模型不确定区域，又使世界模型永远缺少该区域数据。

应引入三种校准：

1. 用真实环境小样本估计世界模型在不同事件上的误差；
2. 对高不确定性和高风险区域强制真实验证；
3. 保留独立回归集，防止闭环只优化当前 evaluator。

### 11.6 数据自进化不是“只保留成功”

高效闭环需要管理完整经验类型：

| 经验类型 | 建议处理 |
|---|---|
| 清晰成功 | 进入任务或技能训练，控制重复度 |
| 高效成功 | 可提高权重，作为动作质量参考 |
| 低效成功 | 保留关键片段，降权绕路与重复动作 |
| 可恢复失败 | 用于恢复策略、critic 或偏好训练 |
| 不可恢复失败 | 用于终止、避障和风险边界学习 |
| 人工接管 | 对接管前状态和纠正动作重点标注 |
| 传感器/系统故障 | 用于异常检测，不直接模仿控制动作 |
| 新颖但未验证经验 | 进入验证队列，不立即加入主训练池 |

### 11.7 自进化系统的稳定性问题

闭环系统至少面临五类反馈风险：

- **选择偏差：** 当前策略只访问自己容易到达的状态；
- **评价器投机：** 生成器找到 evaluator 漏洞，而非真实改进；
- **错误放大：** 自动标签或世界模型错误被反复回流；
- **能力遗忘：** 新失败数据压过旧技能分布；
- **安全探索：** 为覆盖长尾而执行高风险行为。

因此，每轮数据更新都应通过固定回归集、跨场景验证、数据漂移报告、安全门控和版本回滚。

### 11.8 从静态准备到自主 Data Preparation Agent

可按数据决策权限把演化划分为五级：

| 等级 | 系统能力 | 判定边界 |
|---|---|---|
| L0 静态准备 | 人工固定规则、阈值和一次性混合 | 模型反馈不改变数据决策 |
| L1 学习器相关准备 | 用 loss、influence、proxy 或目标分布优化子集/权重 | 仍是离线、一次性优化 |
| L2 失败驱动后训练 | rollout、失败和干预改变下一轮后训练数据 | 通常只有一轮或少数预设轮次 |
| L3 数据引擎 | 持续执行 collect–verify–route–train–deploy | 闭环动作和触发条件仍由人预先定义 |
| L4 数据准备代理 | 自主选择算子与诊断实验、分配预算、判断停止/回滚 | 必须具备因果对照、权限约束和安全治理 |

现有工作已经提供 L2–L3 的强局部证据，但尚没有系统同时证明 L4 所需的算子选择、实验归因、跨学习器迁移、停止、拒绝执行和数据—模型联合回滚。给一个数据引擎加 LLM planner 并不会自动满足这些条件：语言模型可以规划或生成代码，却不能替代物理验证、真机权限和独立审计。

## 12. 代表性大模型与企业 technical report 的数据配方

### 12.1 为什么 technical report 重要

许多最完整的数据准备流程并不以“data preparation”为论文标题，而散落在 VLA technical report 的数据、训练和附录章节中。它们提供规模、来源、格式、筛选、动作表示、标注和混合比例，是理解真实数据引擎的重要证据。与此同时，报告中的结果通常与专有数据和模型耦合，难以独立复现，不能直接当作因果结论。

| DeMaVLA | 大规模双臂数据及在线纠正 | 数据选择、失败驱动后训练、人工 gate | 目标部署性能依赖离线规模和在线纠正的组合 [P148, P186] |

### 12.3 三个可复用的工程模式

**模式一：规范动作空间 + 本体 mask。** 适合大规模跨本体训练，但需要进一步编码控制器和运动链语义。

**模式二：大规模弱对齐预训练 + 小规模强对齐后训练。** 人类视频、UMI、跨本体数据用于视觉—语义—运动先验；目标机器人高质量数据用于动作精度和接触对齐。

**模式三：自动语义化 + 多级质量 gate。** VLM 负责切分和语言，规则/状态负责技术验证，仿真或真机负责物理与闭环验证。

### 12.4 报告之间难以直接比较的原因

不同系统对“小时”“轨迹”“任务”和“成功”定义不同；有些规模包含合成或重放数据，有些只计真实机器人时间；过滤前后数据量也未必同时公布。未来 survey 和 benchmark 应要求统一报告：原始量、保留量、每种变换后的派生量、真实/仿真/生成占比、重复系数、机器人数量、任务数量、控制频率和训练采样比例。

## 13. 如何评价具身数据准备方法

### 13.1 内在指标只能回答“数据看起来如何”

常见内在指标包括：损坏率、同步误差、成功标签准确率、人工偏好、去重率、覆盖度、VLM 标注准确率、轨迹平滑度、物理验证通过率和过滤器 AUROC。它们适合诊断某个算子，但不能单独证明对策略有效。

### 13.2 外在评价必须固定训练预算

数据准备方法应在固定模型、训练 token/step、算力和调参预算下比较。否则保留更多数据的方法可能因为训练更多样本而占优，保留更少数据的方法也可能因为训练轮数更多而占优。建议至少报告：

- 固定优化步数下的策略性能；
- 固定读取样本数下的策略性能；
- 固定总算力或总成本下的策略性能；
- 达到同一成功率所需的数据量和训练成本；
- 不同模型规模下数据排序是否保持一致。

### 13.3 闭环指标是最终标准

对 manipulation，核心指标应包括真实或高保真仿真闭环成功率、完成时间、人工接管率、重试次数、恢复成功率、碰撞/掉落/越界率和跨场景泛化。离线 action MSE、视频相似度或验证损失可作为代理，但应分析它们与闭环结果的相关性。

### 13.4 数据准备的成本也必须计入

自动化流水线可能调用 VLM、世界模型、仿真、轨迹优化和人工审核。若只报告训练节省而忽略准备成本，会高估系统收益。建议统一记录：

```text
Total Cost = collection + storage + preprocessing + labeling
             + generation + verification + training + real evaluation
```

同时报告单位有效数据、单位性能增益和单位新技能的成本。

### 13.5 鲁棒的实验设计

一个有说服力的 data prep 实验应包含以下对照：

1. **原始数据：** 不做筛选或只做最低技术检查；
2. **随机同量子集：** 排除单纯数据量减少的影响；
3. **常见规则：** 成功、长度、平滑度等强基线；
4. **目标方法：** 在相同保留率和训练预算下比较；
5. **Oracle 或人工上界：** 在可行规模上估计空间；
6. **受控污染：** 注入错标签、不同步、重复、失败、idle、动作噪声等；
7. **自然脏数据：** 在真实多源数据池验证；
8. **跨模型验证：** 检查是否只对一个策略架构有效；
9. **跨任务/本体验证：** 检查泛化和负迁移；
10. **消融：** 分析各个算子、评分信号和 gate 的贡献。

### 13.6 建议建立 DataComp-Robot 基准

LLM 领域的 DataComp-LM 通过固定原始数据池、训练代码、算力和评测，使研究者只比较数据处理方案。[P190] 具身领域需要类似基准 **DataComp-Robot**：

- 提供含真实缺陷和受控污染的多源原始数据池；
- 公开统一 schema、机器人描述和数据谱系；
- 允许提交过滤、加权、重标注、增强和混合流水线；
- 固定若干模型规模与训练预算；
- 在离线指标、仿真闭环和小规模真机任务上评分；
- 同时评价性能、泛化、安全、准备成本和可解释性；
- 设置跨本体、长尾技能、失败恢复和分布漂移赛道。

这一基准会把数据准备从不可比较的工程配方转化为可重复的算法研究。

## 14. 从 LLM 数据准备中可以借鉴什么

### 14.1 可迁移的机制

LLM 数据工程已形成较成熟的算子和评测思想。RefinedWeb、FineWeb、DataComp-LM、DoReMi、DSIR、LESS、DEITA、JEST、Self-Rewarding LM、Data-Juicer 和 DataTrove 提供了从预训练到后训练再到递归自生成的机制参照。[P187–P210]

**第一，可组合的数据算子库。** 解析、语言识别、规则过滤、模型打分、去重、隐私清理和格式化被实现为可配置算子。具身领域也需要统一的时序同步、动作转换、轨迹切分、失败识别、物理检查和多模态去重算子，而不是每个实验重写脚本。

**第二，固定数据池和固定训练预算。** DataComp-LM 的价值不只是新过滤器，而是让数据方案可比较。具身领域尤其需要把硬件、仿真和训练预算纳入统一协议。

**第三，学习数据混合。** DoReMi 和 DSIR 说明，可以依据目标分布学习域权重或重采样，而非只靠人工经验。具身领域可把“域”扩展为本体、技能、环境、数据源和训练角色。

**第四，数据谱系和版本化。** FineWeb、Data-Juicer、DataTrove 强调可扩展处理和可复现管线。具身数据经过重定向、重标注、增强和合成后更需要保留父子关系，否则无法定位错误来源。

**第五，用代理训练而非静态质量决定数据价值。** 高质量文本分类器并不总能预测目标模型收益；这与机器人 demonstration curation 的发现一致。小规模训练、影响估计和固定验证集应成为流水线搜索的核心 evaluator。

**第六，后训练数据需要目标相关性、难度和互补性。** LESS 用 optimizer-aware influence 选择针对目标任务的 instruction，DEITA 将质量、复杂度和多样性分开，JEST 说明 batch 内交互可能比逐点排名更重要。[P204, P207–P208] 对 EI 的对应物不是孤立 transition 分数，而是完整的 approach–grasp–place 片段、failure–correction–recovery 组合，以及跨任务/本体覆盖约束。

**第七，自生成闭环必须保留外部锚点。** Self-Rewarding LM 展示“生成候选—自评—构造偏好—更新”的闭环；model collapse 研究则说明，递归地用生成数据替换自然数据会优先丢失分布尾部。[P209–P210] 这不能直接推出机器人策略必然崩溃，但给出明确设计约束：合成/自主数据应累加且保留谱系，不应无审计替换真实数据；generator 和 judge 需解耦，并设置真实 anchor、group floor、canary 与 rollback。

### 14.2 不能直接照搬的部分

LLM 方法通常假设样本相对独立，质量主要来自内容与分布。具身数据还受动作因果、时间同步、本体约束和真实物理影响。因此：

- 文本去重不能替代轨迹级和片段级行为去重；
- 文本质量分类器不能验证动作可执行性；
- 静态验证集损失不能完全替代闭环 rollout；
- 网络数据的规模优势不能直接弥补精确机器人动作的缺失；
- 纯离线数据混合无法发现部署中的新失败模式；
- 数据许可、人物隐私和家庭环境敏感信息在视频和机器人日志中更复杂。

### 14.3 最值得迁移的不是某个过滤器，而是实验范式

LLM 数据研究的最大启发是把数据管线当作可搜索、可比较、可复现的系统。对于具身智能，这意味着研究对象从“提出一种新数据集”转向“在固定原始池和预算下，自动生成更优训练分布”。

### 14.4 从 LLM pretraining / alignment 到 EI 的阶段映射

| LLM 阶段 | 可迁移机制 | EI 对应阶段 | 必须新增的约束 |
|---|---|---|---|
| web pretraining | 固定 pool、过滤/去重、域混合、固定 compute 比较 | VLA 广域预训练 | episode/segment 分组、动作语义、跨本体与真机成本 |
| instruction tuning | target influence、质量/难度/多样性、joint selection | 目标任务/本体适配 | 时序互补、策略诱导分布、失败与恢复语义 |
| preference/RLHF | reward model、偏好对、在线/离线后训练 | rollout、人工接管、reward/critic 后训练 | 物理有效性、稀疏奖励、安全探索和人机纠正边界 |
| self-training | 模型生成、模型判断、多轮再训练 | world model 合成、自主采集、data engine | 独立验证、真实 anchor、闭环漂移、停止与回滚 |

迁移单位应是**实验和控制机制**，而不是直接复制文本质量分类器。文本样本近似可交换；具身数据包含动作因果、控制器、本体、接触和时间信用分配。忽略这些差异，会把“LLM data recipe 的启发”写成类比而不是可检验的研究方案。

## 15. 文献综合：正在形成的八个研究共识

### 15.1 数据准备是编译器、优化器和控制器的结合

它像编译器一样把异构原始记录转换到规范表示；像优化器一样选择、加权和调度数据；又像控制器一样根据训练和部署反馈改变下一轮输入。只把它理解为 ETL 或离线清洗，会遗漏数据价值估计和闭环反馈两个关键环节。

### 15.2 不存在脱离目标条件的统一“高质量数据”

技术有效性可以相对独立判断，但训练价值依赖目标模型、本体、任务、阶段和预算。近期影响估计、数据混合和 curation 研究都支持把质量从标量改写为条件函数。[P049–P066]

### 15.3 最关键的处理粒度是片段和状态转移

整条 episode 的成功/失败标签过于粗糙。NILS、SPARC、ReTVL、SIEVE、Qwen-RobotManip 和 LingBot-VLA 2.0 都在不同形式上使用片段、阶段、primitive、transition 或行为上下文。[P060, P066, P076, P080, P092–P093] 片段级处理是连接筛选、重标注、合成、恢复学习和技能组合的共同接口。

### 15.4 跨本体对齐应同时处理结构和语义

规范向量、mask 和坐标变换解决了输入输出接口，但真正的共享还需要表达运动链、控制器、末端类型和行为语义。否则，不同本体的相同槽位可能提供冲突监督。

### 15.5 生成能力将快速商品化，验证能力会成为壁垒

视频模型、仿真生成和 agentic world building 会持续降低候选数据生成成本。决定系统价值的将是：能否以低成本识别语义正确、物理可行、对策略有增益且安全的样本。验证器应成为独立模型和基准，而不是生成论文的附属过滤步骤。

### 15.6 失败数据的价值来自结构化，而不是数量

盲目加入失败会让 imitation policy 学会错误行为；完全删除失败又失去决策边界、恢复和安全信息。需要把失败切分为错误动作、错误结果、retry、恢复、接管和不可恢复风险，并通过不同目标路由。

### 15.7 数据与模型必须联合版本化

闭环系统中，某条数据的价值取决于生成它的策略和处理它的流水线。每个样本应记录原始来源、采集策略、模型版本、流水线算子、标注器、验证结果、训练角色和后续影响。没有联合谱系，就无法解释性能回归或闭环偏差。

### 15.8 自进化是受约束的连续实验，而不是数据累积

每一轮都应提出明确能力缺口，决定需要哪类证据，对新增数据做同量/同算力反事实 promotion test，并验证旧能力、长尾和安全回归。RECAP 的 checkpoint restart、SOP 的 online 配比边界、LWD 的 offline reference，以及递归生成数据的 collapse 风险共同说明：闭环价值来自相关反馈，也必须由锚点、限制更新率和 rollback 抵消反馈内生性。[P136, P149–P150, P209]

## 16. 关键研究空白

### 16.1 缺少统一的原始数据质量基准

多数论文在私有数据上定义自己的缺陷和评测，导致筛选器不可横向比较。现有工作也常在已高度处理的数据集上再做选择，忽略最早的同步、标定和格式错误。

### 16.2 缺少策略无关与策略相关评价的桥梁

规则、VLM 和表示指标便宜但不总能预测闭环收益；目标策略 rollout 准确但昂贵。尚缺少能够在不同 VLA 架构和训练规模间稳定迁移的数据价值代理。

### 16.3 缺少跨本体动作语义的可学习标准

固定动作槽位和 mask 是实用方案，但不是最终答案。需要把机器人结构、控制接口和动作后果编码为可学习的统一表示，并评估是否减少负迁移。

### 16.4 缺少针对失败、恢复和安全的统一数据 schema

不同系统以自定义方式记录人工接管、retry、终止和碰撞，难以汇聚。需要同时表示意图、错误点、恢复起点、风险类型和允许的训练用途。

### 16.5 缺少生成数据的物理与策略价值 benchmark

现有工作常用视觉质量、人工偏好或仿真成功率评价合成数据。尚缺少从视频/轨迹生成到目标策略增益的完整评测，以及对 world model 偏差的系统分析。

### 16.6 缺少流水线自动搜索和安全回滚

大部分技术报告仍依靠专家手工设计规则、阈值、混合比例和训练阶段。LLM 数据工程已经出现自动选择和管线优化，具身领域尚缺少能处理物理验证、真机预算和闭环风险的统一系统。

### 16.7 缺少数据准备成本的标准化报告

论文通常报告数据小时和下游性能，但很少报告 VLM 标注费用、仿真时长、人工复核、丢弃率、存储和处理成本。无法判断方法是否真正提高端到端数据效率。

### 16.8 缺少可证伪的自主数据准备代理基准

现有 data engine 大多自动执行人工预设闭环，并未自主选择算子、诊断实验、预算和停止条件。应建立受控 benchmark：提供版本化 raw pool、可逆 operator library、固定 learner、仿真与有限隐藏真机 audit、成本/安全约束和人工植入的分布缺口。代理每轮只能看到自己购买的证据，并选择 prepare、train、audit、abstain、stop 或 rollback。评价应包括累计 utility regret、成本、违规、最差组保留、收益预测校准和谱系可重放，而不是只看最终成功率。

## 17. 建议的新研究方向：EvoDataPrep

### 17.1 研究目标

构建一个面向具身训练的自动数据准备代理。给定原始多源数据、目标 VLA、目标本体、任务集合和预算，系统自动生成并迭代优化数据流水线，使固定预算下的闭环性能最大化。

它不直接设计新的 VLA 架构，而是优化 VLA 所看到的训练分布，因此可以作为独立、通用且可实证的研究方向。

### 17.2 系统架构

```text
Raw Data Lake
    ↓
Catalog & Lineage
    ↓
Technical Validator ──→ quarantine / repair
    ↓
Cross-Embodiment Canonicalizer
    ↓
Semantic Segmenter & Labeler
    ↓
Multi-Granular Quality and Value Estimator
    ↓
Pipeline Planner / Operator Search
    ├── filter / weight / route
    ├── relabel / segment / merge
    ├── augment / synthesize / retarget
    └── request new collection
    ↓
Semantic → Geometric → Physical → Policy Gates
    ↓
Training Mixer and Curriculum
    ↓
VLA Training / Simulation / Real Evaluation
    ↓
Failure Miner and Active Collector
    └───────────────────────────────↺
```

### 17.3 九个核心模块

1. **Data Catalog & Lineage。** 统一描述数据源、机器人、传感器、控制器、许可、版本和所有派生关系。
2. **Technical Validator。** 检测文件、同步、标定、图像、状态和动作异常，区分可修复与应隔离数据。
3. **Cross-Embodiment Canonicalizer。** 统一坐标、时间、动作和自由度，并保留本体结构条件。
4. **Semantic Segmenter。** 生成对象、阶段、状态转移、子任务、结果、失败和恢复标签。
5. **Multi-Granular Value Model。** 在来源、episode、片段、transition 和时间步层估计多目标价值。
6. **Operator Library。** 提供过滤、平滑、切分、重标注、镜像、重定向、合成、验证和混合算子。
7. **Pipeline Planner & Experiment Controller。** 根据数据统计、目标任务和反馈搜索算子组合、阈值与顺序，并选择可归因的诊断/训练实验、停止或回滚。
8. **Hierarchical Verifier。** 使用异构模型完成语义、几何、运动学、动力学和策略验证。
9. **Failure Miner & Active Collector。** 聚类部署失败，决定从现有池检索、生成、重放还是重新采集。

### 17.4 可研究的算法问题

**问题一：多粒度数据价值估计。** 如何同时估计整条轨迹、片段和 transition 的边际价值，并把价值从小模型迁移到大 VLA？

**问题二：流水线组合搜索。** 不同算子的顺序会改变结果，例如先切分再筛选与先筛选再切分不同。如何在昂贵的训练反馈下进行 sample-efficient 搜索？

**问题三：跨本体条件价值。** 如何预测一条人类/机器人轨迹对目标本体的可迁移部分，而不是给出整体二值判断？

**问题四：合成数据验证。** 如何用最低真实执行成本，校准 world model、仿真和 VLM 验证器对物理成功的预测？

**问题五：失败数据路由。** 如何自动识别错误、retry、恢复和安全边界，并分配给 imitation、critic、偏好、终止或异常检测目标？

**问题六：闭环稳定性。** 如何防止选择偏差、评价器投机、错误回流和灾难性遗忘？

**问题七：自治权限与可证伪能力。** 如何证明代理不仅能写出 pipeline，还能隔离一次数据决策、预测其收益、迁移到另一学习器，并在超出安全或证据边界时拒绝执行？

### 17.5 一个可落地的第一篇论文方案

**题目方向：** *Can Data Preparation Pipelines Be Optimized for Vision-Language-Action Models?*

**核心问题：** 在固定原始数据池、VLA、训练预算和评测任务下，自动选择数据准备算子，是否能优于人工规则、单一质量评分和随机同量子集？

**建议范围：** 第一篇不必同时解决自动采集和世界模型生成。先聚焦离线多源数据的片段级筛选、重标注、加权和混合，建立可重复 benchmark。

**原始数据池：** 选择 3–5 个公开机器人数据集，统一成共同 schema，并注入可控缺陷：时间错位、idle、动作噪声、错误语言、重复轨迹、局部失败和本体不匹配。保留真实自然缺陷。

**算子空间：** 技术修复、idle 删除、轨迹切分、VLM 状态转移标签、表示去重、互信息/进度评分、目标验证损失评分、片段降权、数据源混合。

**方法：** 用代理 VLA 或小规模训练估计候选流水线价值，再用 bandit、Bayesian optimization 或 learned planner 搜索算子组合；目标函数同时考虑下游成功率、准备成本和数据保留率。

**基线：** 原始数据、成功过滤、手工规则、随机子集、单一质量模型、Re-Mix 类混合、影响估计以及 oracle 人工小规模选择。

**评测：** 固定计算量，在多个策略架构、任务和本体上比较；报告闭环成功率、恢复、安全、泛化、数据量、训练成本和准备成本。

**关键贡献：**

- 首个面向 VLA 的数据准备流水线优化问题定义；
- 一个含受控与自然缺陷的多源原始数据基准；
- 一个多粒度、策略相关的 pipeline search 方法；
- 对“静态质量指标是否预测闭环收益”的系统实证。

### 17.6 后续扩展为数据自进化

第二阶段可加入部署失败回流：系统根据失败聚类选择已有片段、生成反事实、请求人工纠正或安排新采集。第三阶段加入世界模型生成与分层验证，形成完整 EvoDataPrep 数据引擎。

## 18. 建议的正式 survey 论文结构

正式投稿版本可采用以下结构：

1. **Introduction：** 数据规模增长与训练分布问题；为什么 data prep 是独立研究问题。
2. **Background and Scope：** 具身数据类型、VLA 训练阶段、术语与纳入标准。
3. **Problem Formulation：** 原始记录、数据算子、训练角色、条件数据价值和成本目标。
4. **Source Engineering and Acquisition：** 真机、UMI、人类视频、仿真、生成和自主采集。
5. **Ingestion and Cross-Embodiment Standardization：** schema、同步、坐标、动作、频率和本体条件。
6. **Semantic Enrichment：** 标注、切分、重标注、成功/失败/恢复表示。
7. **Curation and Composition：** 规则、表示、信息量、策略相关估值、混合与课程。
8. **Augmentation and Synthesis：** 视觉、几何、轨迹、任务、视频/世界模型生成与验证。
9. **Closed-Loop Data Evolution：** 在线后训练、主动采集、失败回流、车队学习和共进化。
10. **Industrial Data Engines：** 代表性 technical report 数据配方对比。
11. **Evaluation and Benchmarking：** 固定预算、闭环指标、成本和 DataComp-Robot。
12. **Lessons from LLM Data Engineering：** 可迁移机制与具身特有约束。
13. **Open Problems and Research Agenda：** EvoDataPrep 与未来基准。
14. **Conclusion。**

## 20. 结论

面向具身智能的数据准备正在从幕后工程转变为决定基础模型能力的核心研究问题。文献已经覆盖采集、跨本体标准化、自动语义化、筛选、混合、合成和在线改进，但这些环节仍主要由独立方法或手工配方完成，缺乏统一目标、可比较基准和闭环优化。

本综述提出的核心视角是：数据准备的最终产物不是“更干净的数据”，而是**与目标模型、本体、任务、训练阶段和部署环境相匹配的可训练分布**。工业 recipe 表明，规模必须建立在跨本体对齐、训练角色和真实锚点之上；RL/post-training 表明，失败只有在 outcome、时间边界、纠正和用途被表示后才能成为监督；LLM 数据工程表明，最值得迁移的是固定干预、混合优化和递归生成审计。相应地，下一阶段的研究重点应从静态数据集转向可组合的数据算子、片段级价值估计、分层物理验证、失败与恢复路由、固定预算评测，以及根据训练和部署反馈自动更新且能够安全拒绝、停止和回滚的 EvoDataPrep 代理。
